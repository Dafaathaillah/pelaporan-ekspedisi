# P2H Kedatangan Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task.

**Goal:** Require Coordinator approval of a separate arrival P2H before arrival reporting and provide its PDF download.
**Architecture:** Add arrival_p2hs linked to permit units with immutable reviewed revisions; reference the approved inspection from new arrival reports. Reuse checklist and PDF layout while distinguishing arrival review from departure review.
**Tech Stack:** Laravel, SQLite in-memory tests, Inertia/Vue, Dompdf.
**Spec:** docs/superpowers/specs/2026-10-29-arrival-p2h-design.md (approved by user).

## Global Constraints
- Preserve existing departure, legacy report review, internal permits, and escort wait rules.
- Keep site/company/permission checks; no production migration or deployment.
- Work in the existing user workspace; leave unrelated files intact. User explicitly requested implementation; execute inline without another approval round.

## Review Focus
- Cross-company, cross-site, or insufficient-permission users must not submit/review/download.
- Reject requires reason; only the current pending revision may be reviewed, including stale requests.
- Latest rejected or pending revision must not unlock arrivals, even via direct POST.
- Duplicate arrival and inspection submissions must not overwrite records.
- New approved structured P2Hs must remain downloadable after reporting and legacy records must remain functional.
